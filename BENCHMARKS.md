# Benchmark Suite

Метрики не измеряют качество без эталонной разметки. По умолчанию WER, CER и DER — **N/A**. Реальный текст, полученный моделью, не становится ground truth автоматически.

## Воспроизведение

1. Импортировать тестовую запись и обработать выбранным backend до ручного редактирования.
2. Экспортировать JSON. Он содержит `recordingId`, `diagnostics` и исходные интервалы диаризации.
3. Подготовить эталон JSON по `benchmark/reference.example.json`, указав recordingId этой записи.
4. Модели → Benchmark Suite → Импорт эталона JSON. Результат сохраняется в приватном `files/benchmarks` приложения.
5. Повторить на копии того же аудио с другим backend. Сохранять устройство, конфигурацию и версии вместе с результатом. Название backend указано фактически использованное.

Эталон содержит `text` и/или `turns`; отсутствующая часть оставляет соответствующую метрику N/A. Нельзя использовать вручную исправленную стенограмму как исходный ML-результат: встроенный инструмент отказывает в таком сравнении. Импорт benchmark-аудио выполняется обычным импортом в библиотеку; отдельного облачного корпуса нет.

## WER и CER

Текст приводится к NFC и lower case, ё заменяется на е, пунктуация заменяется пробелами, повторные пробелы схлопываются. WER — расстояние Левенштейна по словам / число слов эталона. CER — расстояние по символам без пробелов / число символов эталона. Вставки, удаления и замены стоят по единице. Числительные не нормализуются. Пустой эталон даёт N/A. Значения могут превышать 1, они не являются confidence.

Текущая реализация сравнивает полный последовательный текст записи. При перекрывающейся речи порядок эталонных слов надо фиксировать заранее. Модельные ASR-метрики отдельно на подготовленных одноголосных WAV не смешиваются с метриками полного pipeline.

## DER

Расчёт использует **исходные интервалы диаризации**, не границы распознанных фраз и не ручные назначения. Правила:

- Оценивается вся запись от 0 до audioMs.
- Collar равен 0 ms; удаление окрестностей смены говорящего не применяется.
- Пересечения включены; знаменатель — суммарное reference speaker-time, поэтому в пересечении время учитывается для каждого активного говорящего.
- Глобальная взаимно-однозначная перестановка speaker ID выбирается венгерским алгоритмом по максимуму временного совпадения. Неизвестный участник не получает бесплатного совпадения с несколькими людьми.
- На каждом элементарном интервале miss=max(0,Nref−Nhyp), false alarm=max(0,Nhyp−Nref), confusion=min(Nref,Nhyp)−Ncorrect. Каждый член умножается на длительность интервала.
- DER=(miss+false alarm+confusion)/reference speaker-time. При отсутствии речи в эталоне DER=N/A.

Это явная воспроизводимая конфигурация, не заявление о полной совместимости всех опций md-eval/pyannote.metrics. Библиотечная сверка на публичном корпусе пока не выполнена. Один вариант алгоритма тестируется на перестановке ID, пересечениях, пропусках, ложных срабатываниях и смешении участников.

## Время, память и размер

Worker записывает monotonic elapsedRealtime: подготовку, VAD, диаризацию, ASR и весь pipeline, включая загрузку/инициализацию моделей и проверку SHA-256 после начала измеряемой части. Pipeline RTF = totalMs/audioMs. ASR RTF = время ASR-этапа / полная длительность исходной записи; это не чистая скорость сети на активной речи. В документации запуска указывать холодный или повторный запуск и условия температуры.

`finalPssKb` — один настоящий снимок Android Debug.MemoryInfo в конце обработки. Это **не пиковое потребление**. Peak memory остаётся N/A. `modelBytes` — сумма реально установленных файлов моделей, включая альтернативный backend, если установлен. Время скачивания в RTF не входит.

## Корпус

`benchmark/corpus` намеренно не содержит приватных записей. Для русского ASR smoke test используется WAV из официального архива GigaAM-conversion sherpa. Для отдельного smoke test диаризации — `0-four-speakers-zh.wav` из официальной документации sherpa. Это технические прогоны совместимости без предоставленной reference-разметки: точность N/A. Китайский файл не используется для утверждений о качестве русского ASR.

Для итогового сравнения к хакатону записать с согласия участников 5–10 коротких русских диалогов: тихая комната, шум, перебивания, одинаковые тембры, разные микрофоны. Хранить согласия отдельно; публиковать записи только при явном разрешении. Для каждого файла подготовить дословный текст и интервалы всех участников, включая пересечения.

Реальные результаты размещаются в `docs/host-smoke.json` и отчётах Android, если соответствующий прогон завершён. Linux-результат всегда подписан как Linux, не Android.
