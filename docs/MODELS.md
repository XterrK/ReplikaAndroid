# Модели

В APK встроены четыре модели — семь файлов общим размером 278 127 730 байт (≈ 265 МиБ).
Все работают на CPU через [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) 2.0.1
и ONNX Runtime 1.28.2. Модели не обучались и не дообучались нами.
Наш вклад — выбор моделей по измерениям, конвейер вокруг них и собственная
доработка кластеризации голосов.

Точные пути, размеры и SHA-256 закреплены в [models-lock.json](../app/src/main/assets/models-lock.json).
При первом запуске приложение распаковывает модели и проверяет хеш каждого файла.

## GigaAM v3 E2E — распознавание

**Что это.** Русская модель распознавания от Сбера. Вариант E2E сразу выдаёт текст
с пунктуацией, регистром и цифрами. Используется готовая sherpa-конверсия
(ревизия `a6039be7cee829a9044a69ac0ebaf1c191217c97`), жадное декодирование.

**Почему она.** Организаторы подтвердили: пунктуация и регистр входят в оценку WER.
Значит, нужна модель, которая сама их ставит. Сравнения на открытом наборе FLEURS (русский):

| Сравнение | Результат (WER, меньше — лучше) |
| --- | --- |
| GigaAM v2 → v3 E2E, 32 файла / 670 слов | 8,51% → **5,07%** |
| GigaAM v2 → v3 E2E, все 96 файлов / 1859 слов | 7,48% → **4,79%** |
| Parakeet TDT 0.6B v3 (NVIDIA), те же 32 файла | 8,06% против 5,07%. Веса в 2,9 раза больше (670 МБ). Отклонена |
| GigaAM v3 без E2E, 96 файлов | 6,83% против 4,79%. Без пунктуации и цифр. Отклонена |
| Поиск по лучу (4 гипотезы) вместо жадного | 35 ошибок против 34 на 670 словах. Не включён |

Whisper tiny был экспериментальной альтернативой в ранних версиях и удалён в V1.5 в пользу GigaAM v3.
GigaAM-Multilingual не выдаёт пунктуацию и не имеет русской sherpa-конверсии.

Источники: [MODEL_SELECTION_V1_5.md](MODEL_SELECTION_V1_5.md),
[ASR_QUALITY_V1_5.md](ASR_QUALITY_V1_5.md).

**Как мы её используем сейчас.** Модель та же, но изменилось, что ей подаётся.
Вместо коротких отрезков отдельных говорящих — целый фрагмент речи до 20 секунд
плюс 600 мс звука перед ним. Длинный фрагмент режется в самом тихом месте
последних 4 секунд. Это снизило raw WER на dev с 23,26% до 13,32%.
Подробно — в [TEST_RESULTS.md](TEST_RESULTS.md#качество-текста).

## Silero VAD — поиск речи

**Что это.** Маленькая модель (0,6 МБ), которая отмечает, где в записи есть речь.

**Параметры.** Порог 0,5; минимальная речь и пауза — по 0,25 с; окно 512 отсчётов.
Для очень тихих записей временно усиливается копия сигнала. Исходный звук не меняется.

**Что пробовали.** Более чувствительные настройки (ниже порог, короче паузы)
на dev сначала помогали, но на holdout дали 78/444 ошибок против 73/444 у исходных.
Их отклонили, параметры V1.6 сохранены. Источник: [STEP_03_VAD_WORD_ASR.md](STEP_03_VAD_WORD_ASR.md).

## Pyannote segmentation 3.0 — сегментация

**Что это.** Модель, которая в каждом коротком окне определяет, сколько людей
говорит и где меняется говорящий. На её выходе работает отпечаток голоса.

**Что пробовали.** Шаг окна 0,25 и 0,5 вместо 0,1 ускорил бы обработку.
Также пробовали другую минимальную паузу между репликами. Все варианты ухудшили результат на dev:

| Вариант | Верное K на dev | DER на dev |
| --- | ---: | ---: |
| **Выбранный: шаг 0,1, пауза 0,5 с** | **7/8** | **18,30%** |
| Пауза 0,25 с | 6/8 | 21,61% |
| Пауза 1,0 с | 4/8 | 19,80% |
| Шаг 0,25 | 5/8 | 18,98% |
| Шаг 0,5 | 4/8 | 24,22% |

Источник: [step-04/final-native-parameter-audit.json](../artifacts/test-results/step-04/final-native-parameter-audit.json).

## ERes2Net + наша кластеризация — кто говорит

**Что это.** ERes2Net превращает кусок речи в вектор из 512 чисел — «отпечаток голоса».
Близкие векторы — скорее всего, один человек.

### Сравнение шести моделей отпечатка

Сначала мы проверили шесть открытых моделей. Чтобы сравнить именно модели,
число говорящих передавалось из эталона. В продукте так не делается.

| Модель | Размер, МБ | DER ↓ | Верное K ↑ | Лицензия |
| --- | ---: | ---: | ---: | --- |
| **ERes2Net base zh (наша)** | 39,6 | **27,47%** | 4/8 | Apache-2.0 |
| WeSpeaker ResNet34 LM | 26,5 | 30,21% | 5/8 | CC-BY-4.0 |
| TitaNet small | 40,3 | 29,85% | 4/8 | Apache-2.0 (NeMo) |
| TitaNet large | 101,4 | 40,27% | 3/8 | CC-BY-4.0 |
| CAM++ en | 29,6 | 46,86% | 6/8 | Apache-2.0 |
| WeSpeaker CAM++ LM | 29,3 | 50,21% | 6/8 | противоречивые данные |

Затем проверили автоматический режим: 6 моделей × 14 порогов = 84 варианта,
672 прогона. **Ни один вариант не нашёл верное число голосов хотя бы в 7 файлах из 8.**
Лучшее для каждой модели:

| Модель | Наименьший DER | Максимум верного K |
| --- | ---: | ---: |
| TitaNet large | 22,38% | 4/8 |
| TitaNet small | 24,41% | 5/8 |
| WeSpeaker ResNet34 LM | 27,50% | 4/8 |
| ERes2Net base zh | 27,64% | 4/8 |
| CAM++ en | 46,86% | 5/8 |
| WeSpeaker CAM++ LM | 48,26% | 5/8 |

Вывод: замена модели отпечатка сама по себе не решает проблему.
Нужна другая кластеризация.

### Наша доработка: кластеризация окон

Стандартный конвейер sherpa-onnx сначала делит запись на отрезки, а потом
группирует их. Если один отрезок содержит двух людей, ошибка остаётся.

Наш вариант (в отчётах по этапам он называется C2):

1. Sherpa-диаризация делает черновое разбиение. Порог низкий (0,30), чтобы
   голоса скорее дробились, чем сливались.
2. Из каждого отрезка берутся «чистые» окна по 1,5 с с шагом 0,75 с.
   Для каждого окна считается отпечаток ERes2Net.
3. Окна объединяются иерархической кластеризацией: склеиваются, пока среднее
   косинусное расстояние меньше 0,64. Каждое окно начинает как отдельный кластер,
   поэтому смешанный отрезок можно разделить.
4. Не больше 8 голосов. Мелкий кластер — меньше 2 с или 3% записи — отдаётся
   ближайшему голосу.
5. Вставки другого голоса короче 500 мс между двумя одинаковыми сглаживаются.
6. Каждое распознанное слово получает говорящего по наибольшему пересечению во времени.

Порог подбирался только на dev: 21 значение от 0,25 до 0,45. Единственное
значение, при котором одновременно верное K ≥ 7/8 и DER не выше допустимого
предела (28,89%), — 0,36.

Промежуточный вариант C1 (WeSpeaker ResNet34 + слияние центроидов) тоже прошёл dev,
но хуже переносился на отложенные данные:

| Набор | V1.6: DER / верное K | C1: DER / верное K | **Выбранный: DER / верное K** |
| --- | ---: | ---: | ---: |
| holdout, 5 | 51,55% / 2 из 5 | 20,30% / 3 из 5 | **13,89% / 4 из 5** |
| reserve, 10 | 47,66% / 1 из 10 | 29,24% / 3 из 10 | **22,44% / 5 из 10** |

Плюс выбранного варианта: он использует ту же ERes2Net, что уже была в APK.
Новых весов и лицензий не добавилось.

Реализация: Python — [tools/eval/window_overcluster.py](../tools/eval/window_overcluster.py),
Kotlin — [WindowSpeakerRefiner.kt](../app/src/main/java/ru/replika/domain/WindowSpeakerRefiner.kt)
и [DiarizationRefiner.kt](../app/src/main/java/ru/replika/ml/DiarizationRefiner.kt).
Kotlin-версия сверена с Python на 157 сравнениях, включая 23 набора реальных выходов.

### Ограничение

На естественных записях совещаний AMI метод всё ещё находит лишних говорящих:
6, 8 и 5 вместо 4, 4 и 3. Подробно — в [TEST_RESULTS.md](TEST_RESULTS.md#естественная-речь-ami)
и [LIMITATIONS.md](LIMITATIONS.md).

## Английский язык

| Задача | Модель | Размер | Лицензия |
| --- | --- | ---: | --- |
| Определение языка | Whisper tiny (sherpa-onnx `SpokenLanguageIdentification`, int8) | 103,6 МБ | MIT (OpenAI) |
| Английский ASR | NVIDIA Parakeet TDT 0.6B v2 (sherpa-onnx, int8) | 661,3 МБ | CC BY 4.0 |

Язык определяется по первым ~30 с речи (до трёх проб по 10 с, английский — только при строгом большинстве, иначе русский). Определение верно на 100% стенда (23/23 русских диалога, 5/5 английских). Английский WER на 5 диалогах LibriSpeech: raw 7,78%, только слова 1,26%; через GigaAM та же запись даёт 71,75%. У Parakeet есть пунктуация, регистр и таймкоды токенов (шаг 80 мс), поэтому говорящие назначаются по словам, как и для русского. Подробно — [STEP_07_LANG_EN.md](STEP_07_LANG_EN.md).
