# Speaker IDs: происхождение различий V1.1

Проверено по исходникам и сохранённым JSON. Старые доказательства не изменялись. Различия целых speaker IDs сами по себе не являются дефектом clustering или изменением точности.

## Native labels и хронологическая нумерация

`app/src/androidTest/java/ru/replika/DiarizationTest.kt:26` получает `sd.process(...)` и в строке30 записывает `it.speaker` непосредственно в `android-diarization.json`. Поэтому `docs/test-evidence/android-diarization.json` и `docs/test-evidence/v1.1/android-diarization.json` сохраняют **native labels**: 0, 1, 2, 4, 7, 8, 9. Это7 различных значений. Нельзя считать участников как `max(speakerId)+1`.

`MLComparisonTest.kt:143` сначала вызывает `Alignment.stable(...)`. Этот метод в `app/src/main/java/ru/replika/domain/Transcript.kt:17` сортирует интервалы по началу и переименовывает впервые встреченные неотрицательные labels последовательно с0. Unknown остаётся −1. Производственный Worker тоже вызывает `Alignment.stable` перед сопоставлением и сохранением; это уже было в V1.1, а не новый алгоритм V1.2.

Для automatic `.5` наблюдается следующая биекция:

|---:|---:|
| 0 | 0 |
| 1 | 1 |
| 2 | 2 |
| 4 | 3 |
| 7 | 4 |
| 8 | 5 |

Оба automatic результата имеют11 интервалов и7 различных участников. Одинаковые участки продолжают ссылаться на одинаковые голоса после переименования. `Alignment.stable` не добавляет участников и не улучшает DER: это способ представления локальных labels. ID не является личностью человека и не обязан совпадать между записями или независимыми запусками.

## Разница времени до1ms

Старый `DiarizationTest` преобразует секунды через `(it.start*1000).toLong()`, то есть отбрасывает дробную часть. `MLComparisonTest` и Worker используют `roundToLong()`. Например, первый start317ms в raw JSON соответствует318ms в comparison. Наблюдаемые различия границ0–1ms согласуются с этой разницей преобразования; они не доказывают новую модель или изменение diarization quality.

## Fixed4 — другое условие эксперимента

Сопоставлять формат нужно с automatic `.5`, а не с fixed4. При `numClusters=4` clustering получает известное число участников и возвращает4 ID/10 интервалов, объединяя часть прежней фрагментации. Это реальное изменение разбиения из-за конфигурации. Оно не сводится к переименованию и без временного reference не является доказанным улучшением DER. Automatic `.65` в сохранённом сравнении дал те же7 ID/11 интервалов, что `.5`.

Для будущих exports желательно явно подписывать `speakerIdPolicy=native_labels` либо `first_appearance_zero_based`. Это метаданные для интерпретации, не причина переписывать старые JSON, перенумеровывать ручные подписи Room или менять рабочую модель.

## Положительный пример Smart Review

Оригинальный русский mono pipeline V1.1 имел6 диагностических ASR slices:4 коротких unknown дали пустой текст и не стали строками стенограммы;2 непустых длинных сегмента не имели предупреждений. Поэтому пустая очередь не подтверждает правильный ASR.

Для Whisper четыре таких участка длительностью29/65/91/16ms находятся ниже100ms. В закреплённом `third_party/whisper.cpp-1.7.6/src/whisper.cpp:6844` предусмотрен ранний возврат без декодирования входа короче100ms. Их пустой ответ за1–2ms объясняется этой защитой; это не confidence и не доказанное обнаружение тишины. Новый650ms crop находится выше этого ограничения, однако положительный warning-тест использует GigaAM, не добавляя второе мнение автоматически.

`WarningPipelineTest.completeRealShortSpeechWarningPipeline` подготовлен для V1.2: из существующего публичного WAV с SHA-256 `d8aaaa18a5098d7c6de0595ae7ac1e64cacd0d4022af3595213bdaf23be77e69` выделяются фиксированные реальные отрывки длительностью650ms. Продуктовые VAD/clustering/short-warning параметры и pre-roll100ms не меняются. Каждый отрывок обрабатывает настоящий production Worker; тест не вставляет текст, turns, confidence или причины предупреждений в Room.

Положительная проверка засчитывается только если Worker действительно сохранил непустую гипотезу с вычисленной причиной «Короткая реплика…». Если все кандидаты не дали такой строки, тест сохраняет BLOCKED и завершается неуспешно, а не создаёт демонстрационную реплику. Успешный QA recording имеет ID `integration-v12-warning` и остаётся для UI проверки очереди. Результаты сохраняются в `files/v12-warning-pipeline.json`, `v12-warning-diagnostics.json`, `v12-warning-transcript.json/.txt`; копии запусков — `files/v12-warning-evidence/<runId>/`.

650ms файл — контролируемый crop реального голоса, **не естественный новый диалог и не многоголосный русский корпус**. Его timestamps относятся к новому файлу от0, а исходный sourceOffsetMs хранится отдельно. Модели и исходное аудио не входят в review ZIP. Факт исполнения и итог теста определяются центральным TEST_REPORT_V1_2; создание этого теста само по себе не означает PASS.

## Второе мнение ASR

Автоматическое сравнение каждого сегмента с Whisper не рекомендуется в этой итерации. На одинаковом V1.1 PCM прямой Whisper занимал14.06–15.09s против1.95–2.03s у GigaAM; отсутствует независимый эталон, а Whisper не исправил известный префикс в проверенном Worker. Это не общее ранжирование качества, но доказательств объективной пользы второго мнения пока недостаточно.

Возможная последующая функция — явная кнопка для выбранного фрагмента с отдельной гипотезой, без автоматической замены пользовательского текста, под тем же native gate и с проверкой актуальности ревизии. До разметки корпуса и сопоставимого измерения пользы её отсутствие честнее скрытого тяжёлого inference или фальшивого confidence.
