# V1.2 — протокол сохранности ML и происхождения доказательств

Этот документ описывает исходные факты V1.1 и условия приёмки V1.2. Он **не является отчётом об успешном исполнении новых тестов**. Итоговый статус, точный APK, среда, XML-результаты и новые JSON фиксируются основным интеграционным прогоном в `TEST_REPORT_V1_2.md` и `docs/test-evidence/v1.2/`. Независимые агенты не выполняют параллельный native inference.

## Зафиксированная исходная версия

База сравнения — commit `6e3c8abcd885345b185c2a9131f69eb02e4eb029`. Источники ранее выполненных проверок: [ML_TEST_SUMMARY.md](../v1.1/ML_TEST_SUMMARY.md), [TEST_REPORT.md](../../history/root/TEST_REPORT.md), [fixtures.json](../../test-evidence/v1.1/fixtures.json). Старые JSON и скриншоты не перезаписываются результатами V1.2.

Новая компоновка экранов, вручную добавленные имена и короткие производные WAV эти блокировки не снимают. Для русского диалога действует [протокол согласованной записи](../../test-evidence/v1.1/RUSSIAN_DIALOGUE_PROTOCOL.md); без такого файла automatic/fixed полный русский многоголосный тест не объявляется выполненным.

## Неизменяемые условия сравнения

До исполнения записать Git SHA, APK SHA-256, хеши моделей из `app/src/main/assets/models-lock.json`, размер/хеш входного файла, API, ABI, тип устройства, размер страниц, память и сетевое состояние. Проверить фактическое отсутствие активной сети; наличие моделей в pack само по себе offline-исполнение не доказывает. Модельные файлы и исходное аудио не включать в review ZIP.

Сохранить оба ASR, native bindings и реальный Silero / Pyannote / speaker embeddings. Для продуктового Worker сохранить pre-roll **100 ms**, post-roll **0 ms**, исходную шкалу времени и отсутствие повторной подачи пересекающихся samples. Automatic clustering использует прежний threshold `.5`; известное число участников передаётся отдельно через `expectedSpeakers`. Изменение UI не является основанием для подгонки этих параметров.

При read-only проверке этой итерации diff относительно базы в `app/src/main/java/ru/replika/ml/`, `domain/Transcript.kt`, native C++ и model lock отсутствовал. Это исходная проверка области изменений, а не доказательство исполнения финального APK; перед выпуском сравнение повторяется после интеграции.

## Реальные прогоны и инварианты

| Проверка | Условие принятия и сохраняемое доказательство |
|---|---|
| Полный GigaAM Worker | На исходном публичном WAV статус READY, непустые реальные строки, `source` соответствует GigaAM, prefix «ничьих» сохранён, diagnostics содержит `preRollMs=100`; JSON до ручного редактирования сохранён отдельно |
| Полный Whisper Worker | READY и настоящий исходный текст, backend/параметры записаны; ошибочный префикс не исправляется тестовой подстановкой и не выдаётся за улучшение качества |
| Alignment | `0 <= startMs < endMs <= audioMs`, ASR slices отсортированы и не пересекаются; локальное время каждой выборки переведено в исходную шкалу. Нет требования совпадения между разными backend текст в текст |
| VAD-регрессии JVM | Контекст ограничен краями файла; близкие расширенные spans объединены; разбиение учитывает реальные speaker turns и max chunk; неизменные участки не подаются ASR повторно |
| Диагностика и Room | Все фактически обработанные slices, включая пустые, присутствуют в диагностике; непустые строки Room соответствуют сохранённой гипотезе. Синтетический текст не добавляется вместо отсутствующего ответа |
| Редактирование и экспорт | Ручные текст, имя, speaker ID и reviewed сохраняются отдельно от исходной гипотезы; экспорт читается из актуального Room. Undo возвращает ровно предыдущую строку, не меняя source/timestamps и чужие записи |
| Повторный запуск | Новый процесс после force-stop/relaunch видит сохранённые правки. `ActivityScenario.recreate()` проверяет пересоздание Activity и не заменяет отдельный cold-process тест |
| Повреждённый файл | Worker не падает вместе с процессом, завершает работу понятной ошибкой и сохраняет существующие записи. Отдельный UI-тест IMPORTED проверяет только отсутствие преждевременного prepare плеера / запуска Worker до действия пользователя |
| Отмена / повторный запуск | Не возникает двух конфликтующих native операций; терминальные состояния и прежние записи сохраняются. Отмена WorkRequest не считается доказательством мгновенного прерывания уже исполняющегося JNI |

Точность границ и количество строк сравнивать вместе с сохранёнными spans/turns/slices. Совпадение старых результатов полезно как регрессия, но единичное различие сначала исследуется по входу, модели, параметрам и округлению. Отсутствие повторной подачи samples не доказывает отсутствие семантических повторов или пропусков у ASR.

## Положительный пример Smart Review

`WarningPipelineTest.completeRealShortSpeechWarningPipeline` использует исходный публичный `integration-example.wav` с SHA-256 `d8aaaa18a5098d7c6de0595ae7ac1e64cacd0d4022af3595213bdaf23be77e69`. Он один раз декодирует его в PCM mono 16 kHz, создаёт отрывки реальных samples длительностью до 650 ms и последовательно запускает неизменённый production Worker с GigaAM. Фиксированный список исходных offsets: 0, 1000, 1500, 2500, 4000, 5500, 9800, 10000 ms. Новых голосов, текста, turns и warning reasons тест не синтезирует.

Причина «Короткая реплика возле границы» возникает из настоящего производственного условия: длительность полученной partition менее 700 ms. Остальные поддерживаемые факты — unknown/неоднозначный speaker, одновременно активные разные speaker IDs, разрез длинного интервала. Warning описывает условие анализа и не является вероятностью ошибки. После ручной правки исходная причина может оставаться историческим фактом; закрытие очереди определяется явным «Проверено».

Успех положительного теста требует READY, фактически непустой строки GigaAM, сохранённой вычисленной короткой причины, корректных границ и `edited=false/reviewed=false`. Все попытки, включая пустые и ошибки, остаются в `v12-warning-pipeline.json`; победившие raw diagnostics и экспорты — в `v12-warning-diagnostics.json` и `v12-warning-transcript.json/.txt`. Перезапуски имеют отдельную папку `files/v12-warning-evidence/<runId>/`. QA recording `integration-v12-warning` оставляется для реального UI-теста перехода, прослушивания, исправления и отметки «Проверено».

Если кандидаты не дают непустой строки с вычисленной причиной, положительный сценарий остаётся **BLOCKED**, тест завершается неуспешно. Отсутствующий fixture/model — ошибка предусловий, а не PASS или неподтверждённый skip. Результаты не заменяются вручную созданными SegmentRow.

650 ms crop — контролируемый производный пример одного реального голоса, не новый независимый корпус и не естественный русский многоголосный диалог. Его timestamps отсчитываются от начала нового файла; `sourceOffsetMs`, хеш производного WAV и параметры преобразования объясняют связь с оригиналом. UI-тест с 12 вручную созданными длинными именами проверяет масштабирование picker, а не обнаружение 12 говорящих.

В исходном mono результате пустая очередь не доказывала правильность ASR: четыре коротких unknown slices были пусты. Для Whisper участки 29/65/91/16 ms короче ограничения 100 ms; закреплённый `whisper.cpp 1.7.6` возвращает результат до декодирования такого входа. Время 1–2 ms у этих вызовов не является скоростью полноценного распознавания или confidence тишины.

## Speaker IDs и сопоставимость JSON

Старый `android-diarization.json` экспортирует native labels напрямую; comparison и Worker используют `Alignment.stable` с нумерацией по первому появлению. Для одного automatic результата отображение `0→0, 1→1, 2→2, 4→3, 7→4, 8→5, 9→6` сохраняет те же 7 участников и 11 turns. Разница границ до 1 ms объясняется truncation против round. Подробные source paths и ограничения — [SPEAKER_ID_PROVENANCE.md](SPEAKER_ID_PROVENANCE.md).

Не считать `max(speakerId)+1` числом участников и не перенумеровывать сохранённые ручные имена Room для согласования старых тестовых exports. Fixed 4 действительно меняет кластеризацию; сравнивать его с automatic как простую перестановку ID неправильно. Без reference по времени ни более компактные labels, ни известный k не доказывают улучшение DER.

## Сравнение ASR и опциональное второе мнение

Сравнивать отдельно загрузку, прямой inference на одинаковом полном PCM, VAD, диаризацию и полный Worker с фактическими slices. Первый вызов нового engine и warm-вызовы подписывать отдельно; без перезагрузки и контроля filesystem cache не использовать термин reboot-cold. Core pipeline заканчивается до сериализации/финального commit Room; полное пользовательское wall time измеряется отдельно. RTF всегда содержит явно указанную длительность знаменателя. Снимки PSS — память всего процесса в момент замера, не peak RAM и не память только выбранной модели.

В V1.1 одинаковый прямой PCM дал GigaAM 1.95–2.03 s и Whisper 14.06–15.09 s; сравнимого независимого эталона качества нет, а известный префикс Whisper в Worker не восстановил. Эти наблюдения не обосновывают автоматический Whisper для каждой реплики. В V1.2 второй ASR не должен скрыто увеличивать стоимость обработки или заменять ручной текст.

Обоснованный будущий вариант — явное действие для выбранного отрывка, отдельная альтернативная гипотеза, тот же native gate, отмена в доступных пределах и проверка актуальности ревизии перед применением. Полезность нужно подтвердить размеченными независимыми примерами и сопоставимым временем/памятью; пока функция остаётся исследовательской и не заявляется реализованной.

## Как выставлять итоговый статус

- **WORKING** — конкретный сценарий действительно исполнен на указанном APK/устройстве; перечислены проверенные ограничения и сохранены доказательства.
- **PARTIAL** — выполнена только часть сценария либо измерение не покрывает требуемую среду/качество.
- **BLOCKED** — отсутствует вход, разрешённое устройство, reference или требуемая среда; прежний успех другого сценария блокировку не снимает.
- **NOT IMPLEMENTED** — функция отсутствует, например мгновенное native abort или автоматическое второе мнение ASR.

Новые скриншоты подтверждают отображение настоящего состояния приложения, но не заменяют JSON, Room/экспорт-проверки и отчёт instrumentation. Принятие ML-регрессии — централизованный результат интеграции; этот протокол и статический аудит сами по себе не дают V1.2 статус PASS.
