# REPLIKA V1.2 — сравнение пользовательских сценариев

Самостоятельная оценка выполнена по исходникам, всем 19 настоящим кадрам V1.1 и новым Android screenshots V1.2. Поведение подтверждается отдельными тестами и Room/JSON-доказательствами; изображение само по себе не доказывает правильность распознавания или слышимый звук.

База — `validation/v1.1`, commit `6e3c8abcd885345b185c2a9131f69eb02e4eb029`. Среда текущей проверки — Android 15 / API 35, x86_64, страницы 4096 bytes, AVD без реального аудиовхода. Основной профиль: 432×936 px / 384 dp / font scale 1.0. Компактный: 360×640 px / 360 dp / font scale 1.3. Полная конфигурация — [environment.json](../../test-evidence/v1.2/environment.json).

## Визуальная система и её пределы

Сохранена тёмная сине-графитовая идентичность. Blue обозначает действия и позицию воспроизведения; mint/violet и дополнительная палитра связывают участников с timeline. Основной текст 16 sp / 24 sp, метаданные 12–13 sp; системный font scale не отключён. Декоративных градиентов, glass и подменных экранов нет.

Это не доказательство удобства для всех пользователей. Конкретные компромиссы, видимые в новых кадрах:

- На [компактной Library](compact130-01-library.png) видна одна полная запись и начало второй. Двухстрочный placeholder поиска расходует высоту; следующий проход может упростить текст поиска.
- При [font scale 1.3 и открытой IME](23-product-editor-keyboard-compact130-360x640.png) одновременно видно около трёх строк длинной реплики; остальное требует прокрутки. Верхняя подпись поля может оказаться у края viewport. Save доступен, но чтение длинного текста в таком состоянии остаётся тесным.
- [Длинное имя в Workspace](22-product-workspace-compact130-360x640.png) ограничено двумя строками с ellipsis. Полная подпись доступна в picker/редакторе. Цвета повторяются после 10 ID; номер и имя обязательны для различения.
- На [компактной ошибке](34-product-corrupt-worker-recovery-compact130-360x640.png) Retry находится ниже первого экрана и требует прокрутки. Snackbar временно перекрывает часть нижнего текста, как в [Undo](24-product-saved-undo-compact130-360x640.png).
- Закрытие редактора, фильтр и часть настроек находятся сверху. Удобство одной рукой на телефоне не измерено; проверки TalkBack и независимая пользовательская оценка ещё не проведены.
- Undo ограничен последней правкой реплики текущей сессии; это не история изменений и не отмена имени/названия/удаления. SavedInstanceState сохраняет черновик при Activity recreation, но не обещает его постоянного хранения после force-stop.

## Последняя проверка обнаруженных отклонений

В промежуточной сборке найдены три конкретных отклонения: тёмные status bar icons в тёмных sheet, разрыв слова «Проверенные» в компактном Review и playhead 660 ms при длительности 650 ms. Они устранены и проверены повторным полным прогоном. [Редактор](05-segment-editing.png) и [picker с IME](29-product-speaker-picker-keyboard-compact130-360x640.png) имеют светлые системные иконки; [кнопка Review](compact130-14-smart-review-real-warning.png) сохраняет целое слово; [playhead](compact130-16-smart-review-reviewed.png) ограничен 650 ms. [UI JSON](../../test-evidence/v1.2/v12-review-queue-ui.json) фиксирует `subsecondClockClamped=true`, [Review tests](../../test-evidence/v1.2/android-compose-ui.txt) и [compact tests](../../test-evidence/v1.2/android-compact130.txt) завершились PASS. Полные показатели PSS/RTF также видны на [компактном кадре Models](compact130-35-models-metrics.png).

Ранние скриншоты с fade/двойным текстом, белым окном после resume и преждевременным Library вместо setup сохранены в [истории попыток](../../test-evidence/v1.2/attempts/). После ожидания native window/compositor новые кадры 21/24/25 непрозрачны, 28 показывает Workspace, 33 — настоящий setup. Это исправление сбора доказательств, не основание объявлять старые изображения стабильным glass-интерфейсом.

## ML и внешняя приёмка

[Регрессионное сравнение](../../test-evidence/v1.2/ml-regression.json) дало 6 PASS по сохранённым гипотезам, временам, ID и конфигурациям. Новые Android-прогоны реальны; сами равные JSON не доказывают качество ASR. Короткий mono crop не заменяет русский диалог нескольких людей. Физический arm64, русский многоголосный end-to-end, API 36/16 KiB runtime, длительные записи, peak RAM и нагрев остаются вне подтверждённой области. Дополнительно вручную выполнен DocumentsUI → импорт M4A → fixed1 → настоящий Worker → Room → UI → JSON chooser: [proof](../../test-evidence/v1.2/saf-m4a-fixed1-proof.json). Он относится к предыдущему APK `5cc933fe…4909` и помечен **SUPPLEMENTARY**; финальный APK после правки export sheet проверен актуальными автоматическими наборами. Mono M4A не заменяет русский диалог.

Материалы предназначены для независимого Human Review; внешнее UX-одобрение ещё не получено.
