# Независимая приёмка V1.2

Сверьте APK SHA-256 с TEST_REPORT_V1_2.md. Архив ревью не содержит APK, моделей или аудио. Эмуляторные проверки не заменяют физический arm64. Используйте только допустимые тестовые записи; микрофон телефона — с согласия участников и владельца.

1. Установите debug APK с `adb install -r`, сохранив данные. Откройте «Модели», импортируйте offline pack и дождитесь проверки. Малый VAD должен показывать КБ, не 0 МБ. На главном экране видны названия моделей и понятные показатели; сырой JSON открывается отдельно.
2. В Library проверьте список, поиск по названию/тексту, импорт WAV/MP3/M4A. Приветственный блок не должен вытеснять записи. Меню записи → удалить → отмена сохраняет запись. Подтверждение удаляет её стенограмму и принадлежащую ей копию аудио; исходник в Downloads и модели сохраняются. Для Processing удаление недоступно.
3. Без сети запустите GigaAM, затем Whisper на одном допустимом WAV. Выберите автоматическое либо известное число участников. Стадии соответствуют настоящему Worker; нет вымышленных процентов/ETA. Двойной запуск не создаёт конкурирующую задачу. Отмена может ждать текущий native call.
4. В Workspace нажмите реплику: плеер переходит к её началу и останавливается у конца. Проверьте pause/resume, ±10 s, waveform seek и скорости. Цвет таймлайна совпадает с участником. Подсветка относится к целой реплике. Уход в фон ставит плеер на паузу.
5. Откройте меню реплики. Прослушайте участок, измените текст, выберите говорящего. В списке 10+ вручную заданных участников найдите длинное имя поиском; горизонтальная прокрутка не требуется. До сохранения виден статус правки. Back/закрытие с правкой запрашивает отказ от изменений. Клавиатура не должна перекрывать сохранение; содержимое прокручивается.
6. Сохраните исправление и воспользуйтесь «Отменить правку» в уведомлении. Отмена восстанавливает предыдущее состояние всего фрагмента, включая speaker ID и reviewed. Это отмена последнего изменения текущей сессии; после перезапуска история отмены не обещается. Повторите правку без отмены, переименуйте участника. Force-stop → запуск → экспорт JSON/TXT/SRT должны содержать сохранённую версию.
7. Smart Review: для реальной короткой реплики проверьте объяснение, интервал, участника, прослушивание и редактор. «Проверено» убирает фрагмент из очереди; он доступен в проверенных. Пустая очередь явно не гарантирует точность ASR. Тестовый WAV-отрывок описан в ML_REGRESSION_PROTOCOL.md; предупреждения не вставляются вручную.
8. Повторите пункты 2, 4–7 при font scale 1.3 и на компактном экране. Проверьте длинный текст/имена, светлую клавиатуру и bottom sheet. Отдельно оцените удобство одной рукой: верхние настройки и закрытие редактора требуют движения к верхней части экрана.
9. Повреждённый файл должен дать русское объяснение с действием восстановления. Диагностика сохраняет исходную ошибку отдельно. Открытие ещё не обработанной записи не должно запускать скрытое воспроизведение или показывать Source error.
10. С разрешения проверьте реальный микрофон, отказ/выдачу разрешения, ранние отсчёты, pause/resume/save и возврат из фона. Уровень не является калиброванным SPL. На AVD без аудио этот сценарий подтверждает лишь UI/жизненный цикл.

Для физического устройства: [инструкция подключения](../../test-evidence/v1.1/PHYSICAL_DEVICE.md). Для добровольного русского диалога: [протокол и разметка](../../test-evidence/v1.1/RUSSIAN_DIALOGUE_PROTOCOL.md). Проверки нехватки места, длинных записей, нагрева и сторонних Share receivers выполняйте на отдельном тестовом устройстве, не заполняя личный телефон.

Фиксируйте среду, шаги, ожидание, фактический результат, статус WORKING/PARTIAL/BLOCKED/NOT IMPLEMENTED и путь к доказательству. Скриншот доказывает отображённое состояние, но не качество ML или слышимый звук.
