# REPLIKA V1.3 — ручная приёмка

Это кандидат для проверки, не утверждение об устранении automatic diarization или пяти обрезаний vivo. В ZIP включены APK, его SHA-256, исходники изменений, пять отчётов и тестовые evidence. Приватные резервные копии, пользовательское аудио и базы в ZIP не включены. `v1.3-delivery.json` указывает commit исходников.

## Безопасное обновление

Установите V1.3 поверх V1.2.1 с сохранением данных. Не удаляйте приложение и не очищайте хранилище. Подпись APK совпадает со старой, applicationId `ru.replika.offline`, code 5. Если установщик отклоняет подпись, остановитесь и сохраните существующие записи. Открытие старой стенограммы не запускает ASR.

## Быстрый UX-review

1. Откройте старую запись с ручными правками, прослушайте точный физический фрагмент.
2. Переключитесь «Диалог → Чтение → Диалог»: текст и правки должны совпадать, inference не запускается.
3. Скопируйте чистый текст; не должны появляться постоянные имена, временные метки или служебный заголовок.
4. В диалоге измените одну реплику, сохраните, снова откройте чтение. Проверьте сохранность после перезапуска приложения.
5. Короткие паузы одного известного голоса объединяются в группу; другой голос, overlap, unknown и длинная пауза создают отдельную группу. Исходные интервалы, play/edit каждой части остаются в диалоге.
6. Новые PNG `01-dialogue-controlled.png` и `02-reading-controlled.png` используют специально созданный UI fixture; их текст не выдан за inference.

## Проверка на остывшем vivo

Создайте новую запись через импорт копии исходного монолога, сохранив старую. Выберите GigaAM, «Один говорящий», обычную нагрузку. Проверьте один участник, все известные начала слов, оригинальные границы файла и навигацию. Сохраните техническую диагностику. Следующий профиль сравнивайте после охлаждения, с тем же входом. При SEVERE длительные прогоны не продолжайте. Тестовые команды thermal override из исходников предназначены только для эмулятора.

Фиксированный состав проверяйте на записи с известным числом участников. Автоматический — на независимых записях, с ручной проверкой false splits и false merges; сейчас этот режим нельзя считать исправленным. Для boundary review нужны слышимые слова до/после VAD-границ и жёстких 20 s разрезов, не только визуальный текст.

`Модели → Диагностика → Технические данные → Поделиться JSON` экспортирует private данные, включая гипотезы и название; передавайте их осознанно. Для технического системного журнала с ADB используйте только `adb logcat -s ReplikaPerf:I`, без общего сбора журналов других приложений. Не публикуйте запись или стенограмму без согласия её участников.
