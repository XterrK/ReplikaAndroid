# Независимая проверка REPLIKA V1.1

Сначала прочесть TEST_REPORT и PROJECT_STATE: PASS на x86_64 emulator не означает PASS физического arm64. Инструкция телефона — `docs/test-evidence/v1.1/PHYSICAL_DEVICE.md`; русский многоголосный корпус — `RUSSIAN_DIALOGUE_PROTOCOL.md`. Все записи должны быть допустимы к тестированию.

1. Установить APK с совпадающим SHA-256 из отчёта. Импортировать offline pack в «Модели», дождаться проверки SHA-256 всех наборов. Повреждённый ZIP должен давать понятную ошибку и сохранять уже проверенные веса.
2. Без сети импортировать WAV, MP3 и M4A через системный picker. Выбрать backend в «Модели». В рабочем экране выбрать автоматическое число говорящих или явно указать число. Ошибка ввода должна блокировать запуск.
3. Нажать обработку дважды; убедиться, что нет параллельного inference для одной записи. Повернуть экран, уйти в фон, вернуться. При отмене дождаться текущей native операции; «Отмена запрошена» не является мгновенным abort. Открытие уведомления ведёт в приложение, отдельной мгновенной отмены в уведомлении нет.
4. В готовой стенограмме нажать реплику из паузы: начинается её исходный фрагмент. Проверить остановку на границе, ±10 s, waveform seek, смену скорости, подсветку по текущему времени. Смартфонный аудиотракт проверяется отдельно от состояния плеера в тесте.
5. Через меню реплики открыть редактирование; вызвать клавиатуру; прокрутить до участников, отметки проверки и кнопки сохранения. Изменить текст и speaker ID, переименовать участника. После force-stop и повторного открытия проверить данные и экспорт TXT/SRT/JSON.
6. В Smart Review посмотреть вычисленные причины, фильтр участника и переход к следующему предупреждению. После ручной отметки карточка уходит из очереди. Ноль предупреждений означает пустую очередь; это не доказательство отсутствия ошибок ASR.
7. С согласия владельца протестировать настоящий микрофон: отказ/выдача разрешения, пауза/продолжение, фон, сохранение. Автозапись реального телефона в этой итерации не выполнялась.
8. На отдельном тестовом устройстве проверить нехватку диска, прерывание импорта/загрузки и повтор. Не заполнять личный телефон искусственными файлами. Сохранить существующую готовую стенограмму перед повторной обработкой; ошибка не должна удалить её строки.
9. Для русского диалога проверить слова и speaker assignment по независимому эталону, включая близкие смены, короткие ответы, silence и overlaps. Сохранить исходный JSON до ручных правок и отдельный JSON после.

Каждую проверку записывать: WORKING / PARTIAL / BLOCKED / NOT IMPLEMENTED, среда, действие, ожидаемое, фактическое, файл доказательства. Скриншот или компиляция сами по себе не доказывают качество распознавания.
