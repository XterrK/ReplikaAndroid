# Шаг 10. Пунктуация на стыках фрагментов: гипотеза проверена и отклонена

Дата: 07.11.2026. Только стенд на ПК; приложение не менялось.

## Что заметили

Главная метрика — WER с пунктуацией и регистром. На dev она 13,1%, а без
пунктуации — 3,0%. Значит, большая часть ошибок — знаки и регистр.

Разбор сохранённых результатов текущего конвейера (dev + holdout + reserve,
1703 эталонных слова):

| Тип расхождения | Ошибок |
| --- | ---: |
| Знак препинания (слово верное) | 79 |
| — из них в конце нашего фрагмента распознавания | 34 |
| — «!» в эталоне, «.» у нас | 16 |
| Регистр (слово верное) | 37 |
| — из них заглавная в начале нашего фрагмента | 12 |
| Само слово (замена, пропуск, вставка) | 53 |
| «ё» / «е» (жюри не считает) | 9 |

Около 46 ошибок приходятся на стыки фрагментов: модель слышит паузу как конец
фразы, ставит точку и начинает следующий фрагмент с заглавной, а в эталоне
фраза продолжается.

## Гипотеза

Склеивать соседние фрагменты речи, если пауза между ними короткая, в один
фрагмент распознавания (не длиннее 20 с), чтобы модель слышала фразу целиком.
Сейчас паузы короче ~0,6 с уже склеиваются за счёт 600 мс контекста.

На стенде добавлены выключенные по умолчанию параметры `bridge_gap_ms`
(максимальная пауза для склейки) и `bridge_same_speaker` (склеивать, только если
по обе стороны один говорящий по диаризации). Параметр выбирали по dev, holdout
и reserve использовались только для проверки.

## Вывод

На наборах, которые не участвовали в подборе, оба варианта хуже текущего
конвейера. Выигрыш на dev почти целиком дал один файл (`dev-04-expressive`),
то есть это шум маленького корпуса, а не закономерность. В приложение изменение
не переносится; конвейер по умолчанию прежний.

Исходные выходы прогонов лежат вне репозитория (`C:\R\exp-punct`). Повторить:
`tools/eval/run.py --config configs/eval/vad-words-context600-bridge1200[-same].json`.
