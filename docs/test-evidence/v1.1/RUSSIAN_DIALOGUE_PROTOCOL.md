# Русский диалог: BLOCKED до предоставления допустимого исходника

На 2026-10-31 доступен только русский одноголосный публичный пример и китайский четырёхголосный пример. Полный русский многоголосный VAD → diarization → ASR → alignment → Room → UI → export не выполнен. Отдельный китайский clustering test и русский mono pipeline не закрывают этот пункт.

## Получение материала

Записать с добровольным согласием 2–3 взрослых участников 3–5 минут WAV mono 16 kHz (либо исходный M4A с сохранением оригинала). До записи объяснить локальную обработку, цель тестирования, срок хранения, доступ рецензентов и возможность отказаться. Согласие на тестирование и согласие на распространение записи — отдельные решения. Не включать личные сведения; использовать псевдонимы A/B/C. Согласия и исходники держать вне Git и review ZIP.

План: 10 s тишины; представление псевдонимами; по одной длинной реплике 15–25 s; последовательность коротких ответов «да», «нет», «хорошо»; смена участника с паузой <300 ms; смена без паузы внутри общего VAD; 5 s тишины; согласованное перебивание; одновременная речь; спокойное завершение. Не синтезировать дополнительные голоса из одного диктора и не выдавать это за настоящий диалог.

Создать минимум 2 разные записи для настройки и 2 независимые для оценки. Сначала зафиксировать эталоны и split; не выбирать параметры по test split. Желательно разные комнаты и наборы участников. Это минимальный проверочный набор, не репрезентативная оценка качества.

## Ручной эталон

Вручную прослушать исходник. Таблица TSV UTF-8:

```text
recording_sha256	start_ms	end_ms	speaker	text	overlap_group	note
```

Каждый реальный речевой интервал имеет отдельную строку. Перекрывающиеся участники имеют независимые строки с общей overlap_group. Время привязано к оригинальному файлу, не к VAD-обрезкам. Записывать фактически произнесённое, включая повторы; не копировать гипотезу модели. Неразборчивость отмечать отдельно, правило исключения из WER фиксировать до оценки. Вторая проверка слушателем — желательна. Для приложения конвертировать в схему `benchmark/reference.example.json`; значения example не являются данными теста.

## Выполнение и приёмка

1. Зафиксировать хеш аудио, телефона, API, ABI, page size, версии и хеши моделей, APK SHA, backend, numClusters/threshold и VAD параметры.
2. Импортировать оригинал через системный picker. Выполнить GigaAM полный pipeline в automatic, затем на независимой копии с известным числом участников. Сохранять нетронутый export JSON и диагностику до правок.
3. Проверить каждую смену голоса, короткие ответы, длинные реплики, тишину, перебивания, близкие реплики, глобальные timestamps. Сверить пропуски/дубли слов с эталоном. Проверить стабильность ID в пределах записи, а не совпадение ID между запусками.
4. В UI нажать сегменты и проверить исходный звук; исправить текст/ID, переименовать участника; force-stop/relaunch, экспортировать TXT/SRT/JSON; сравнить с Room и правками.
5. WER/CER измерять до правок, DER по исходным diarization turns, отдельно отметить overlap. Не оценивать speaker ID только числом кластеров. Приложить список дефектов с временами и фактический JSON без демонстрационных реплик.
6. Повторить тот же pipeline с Whisper, сохраняя одинаковые ограничения. Качество и скорость публиковать с ограничениями выборки.
