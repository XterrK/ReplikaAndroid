## Как работает определение языка

1. VAD, нарезка и диаризация выполняются как раньше.
2. Из первых ~30 с речи по VAD-фрагментам собирается до трёх проб по 10 с. Соседние фрагменты склеиваются, хвост короче 1 с отбрасывается.
3. Whisper tiny (`SpokenLanguageIdentification` из sherpa-onnx) возвращает код языка для каждой пробы.
4. Английский выбирается только при **строгом большинстве** проб `en`. Ничья, тишина, другой язык, ошибка или отсутствие модели LID дают русский.
5. `ru` → GigaAM v3 E2E, без изменений. `en` → Parakeet TDT v2. В памяти одновременно находится только один распознаватель; английская модель загружается только при необходимости и освобождается после распознавания.

Словные таймкоды у Parakeet работают. По метаданным модели `subsampling_factor=8`, значит токены лежат на сетке 80 мс, и это проверено на хосте: все фрагменты английского стенда прошли через `VadWordPlanner` со статусом `supported`, без отката на целый фрагмент. Поэтому назначение говорящих по словам работает и для английского (cpWER 12.37%, DER 19.63% на C2).

**Посегментный режим (экспериментальный, по умолчанию выключен).** Язык определяется для каждого ASR-фрагмента. Фрагменты короче 1.5 с наследуют решение по файлу. Сначала распознаются все русские фрагменты, затем все английские, после чего реплики сортируются по времени.

## Android: что изменено

- `domain/LanguagePlan.kt` — чистые правила (пробы, голосование, порядок распознавания, плашка), 9 JVM-тестов. Python-зеркало `tools/eval/language_id.py` с теми же тест-кейсами.
- `ml/LanguageRouting.kt` — LID на sherpa-onnx с безопасным откатом на русский. JNI-символы `SpokenLanguageIdentification_*` есть в обоих `libsherpa-onnx-jni.so` (arm64 и x86_64).
- `ml/AsrEngine.kt` — новые `ParakeetEngine` и `RoutedAsrEngine` (один распознаватель за раз, ленивая загрузка английской модели). `GigaAmEngine` не тронут.
- `ml/ProcessingWorker.kt` — минимальная точка вызова (+36 строк): решение о языке перед загрузкой ASR, маршрутизирующий движок, порядок фрагментов, два ключа WorkData. Диаризация и импорт не тронуты. Задания без ключа `languageMode` (созданные до обновления) обрабатываются как русские.
- `ml/ModelManager.kt` — `groupReady`, `requireEnglishReady`, две новые строки на экране «Модели» (их можно скачать и удалить, как остальные).
- UI. В панели обработки рядом с выбором числа говорящих появился блок «Язык записи: Авто / Русский / English» (по умолчанию «Авто»). При «Авто» есть переключатель «Определять язык для каждого фрагмента» с пометкой «Экспериментально». В шапке стенограммы — плашка `RU · GigaAM` / `EN · Parakeet` / `RU + EN` с меню «Распознать заново как English / русский / язык автоматически» и подтверждением, что ручные правки будут заменены. Язык хранится в диагностике (`asrLanguage`); в JSON жюри он **не** добавляется.
- Gradle: флаг `-PreplikaLanguageMode=auto|ru` (по умолчанию `auto`). Значение `ru` возвращает поведение «только GigaAM».

## Что не проверено и риски

1. **Ничего не запускалось на Android.** Нужны прогон на эмуляторе или телефоне (RU и EN файл, «Распознать заново как …», посегментный режим), UI-тесты и скриншоты в обеих темах и с крупным шрифтом. Новые экраны видны только в коде.
2. **Время на ARM неизвестно.** «Авто» теперь включено по умолчанию, поэтому каждая русская запись дополнительно платит за LID: загрузку Whisper tiny, до трёх проб и хэширование 104 МБ при проверке моделей. Для английской записи добавляется хэширование 661 МБ и загрузка Parakeet. На ПК это ~1–2 с, на эмуляторе может быть в разы больше. Если это ударит по RTF, можно собрать `-PreplikaLanguageMode=ru`.
3. **Первый запуск станет дольше**: распаковка и проверка ~1.04 ГБ вместо ~0.28 ГБ. Хранить .onnx в встроенном ZIP без сжатия (STORED) ускорило бы распаковку ценой размера APK, но этого я не делал.
4. Пиковая RAM с Parakeet на эмуляторе не измерена (веса 652 МБ, загружаются только после выгрузки GigaAM).
5. Английский стенд — чистая начитка книг (LibriSpeech), разговорный английский не представлен. Смешанные файлы — синтетическая склейка двух монологов-монтажей, не живая речь с переключением языка.
6. Кроме ручных тестов Python и Kotlin на одинаковых входах, паритет host↔Android для LID и Parakeet не проверялся.
