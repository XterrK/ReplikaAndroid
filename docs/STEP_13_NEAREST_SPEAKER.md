# Шаг 13. Слова вне интервалов диаризации получают ближайшего говорящего

Дата: 07.11.2026.

## Проблема

Время слова в нашем конвейере — оценка по моменту выдачи токена распознавателем, а не
точное выравнивание. Слово часто оказывается на несколько сотен миллисекунд вне всех
интервалов диаризации (например, «Да,» на 0,40–0,44 с, когда первый говорящий начинается
с 0,5 с). Раньше такое слово становилось отдельной репликой «неизвестный говорящий» с
крошечным интервалом. В JSON для жюри она получала ближайшего говорящего, но оставалась
отдельной строкой, что портило таймкоды и диаризацию. На стенде так выглядели 21 реплика
из 185 (11%).

## Решение

Слово, которое не пересекается ни с одним известным интервалом, получает говорящего
ближайшего интервала, если до него не больше 1,5 с, и склеивается с соседней репликой.
Ничьи (слово поровну у двух людей) и участки, которые диаризация сама пометила как
неизвестные, по-прежнему остаются неизвестными. Kotlin:
`VadWordPlanner.nearestSpeaker` / `NEAREST_SPEAKER_MS`; стенд:
`tools/eval/vad_words.nearest_speaker` (переменная `REPLIKA_NEAREST_SPEAKER_MS=0`
возвращает прежнее поведение).

| --- | --- | --- | --- | --- |
| dev | 22,06% → **21,21%** | 824 / 785 → **800 / 693 мс** | 18 → **11** | 7 → 1 |
| holdout | 18,36% → **17,95%** | 610 / 704 → **597 / 704 мс** | 11 → **8** | 3 → 0 |

WER (с пунктуацией и без) и cpWER не изменились: текст тот же, меняется только
принадлежность отдельных слов. Улучшение одинаково по направлению на всех трёх наборах,
включая те, по которым ничего не подбиралось. Порог 1,5 с не подбирался.

JVM: 248 тестов, 0 падений; добавлен `NearestSpeakerTest`, прежние тесты «не придумывать
говорящего» для ничьих и явно неизвестных участков проходят без изменений.
