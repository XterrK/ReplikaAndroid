# REPLIKA V1.3 — результаты первого физического теста

Дата работы: 4 ноября 2026. База: `2f84a633f5c3b51accd99ac7510db70570f61dde`. Это продолжение существующего приложения, applicationId `ru.replika.offline`, Room schema 1. Push не выполняется.

## Наблюдения пользователя

На vivo X300 монолог около четырёх минут обрабатывался более пяти минут; автоматически появились 11 участников; показывалось ожидание охлаждения; паузы дробили мысль; примерно пять начал реплик были обрезаны. GigaAM понравился больше Whisper tiny для русского. Интерфейс, редактирование, аудионавигация и экспорт получили положительную оценку. Нужны представления «Диалог» и «Чтение».

Это сообщения пользователя, а не воспроизведение в этой сессии. Исходная запись и диагностический trace vivo отсутствуют в проекте. В доступных Linux/Windows ADB физического телефона нет. Доступен только эмулятор API 35 / x86_64. Нельзя считать исправленными именно пять границ или 11 участников этой записи.

## Что установлено аудитом

- Предыдущее приложение само формировало фразу «Устройство перегрето · ожидание охлаждения», когда Android PowerManager возвращал SEVERE или выше. Это установленный источник строки в приложении; нет логов, чтобы проверить ответ OEM во время физического теста или исключить дополнительное системное предупреждение.
- V1.2.1 вызывала полный Pyannote/embedding/clustering даже при `expectedSpeakers=1`, читала весь PCM в FloatArray. Теперь режим одного говорящего обходится без этой стадии.
- `RandomAccessFile.readFloat()` использовался для каждого сэмпла. Свежий прогон старого APK на эмуляторе: 11 290 ms аудио, 21 455 ms обработки; чтение для диаризации 4 259 ms, суммарное ASR-чтение 3 466 ms. Это измеренная потеря времени на AVD, а не доказанная причина задержки vivo.
- Pre-roll 100 ms добавлялся перед выравниванием; выравнивание могло снова создать маленькие неизвестные фрагменты на границах диаризации. Новый planner сохраняет короткие однозначно примыкающие края внутри той же VAD-области, помечая их для проверки.
- ML-этапы уже были последовательны и защищены общим mutex. Ускорение нельзя приписывать устранению параллельного запуска, которого не было.
- Автоматическое число кластеров на публичном четырёхголосном китайском fixture уже было неверным в старых evidence. Это известный дополнительный пример, не запись пользователя.

## Реализация и пределы

Три режима говорящих доступны явно. Фиксированный режим использует native `numClusters`; автоматический сохраняет число без глобального ограничения. Изменение универсального порога по одному примеру не принято: host-проба .5/.7/.85 дала 7/5/5 участников вместо 4. Автоматическая диаризация остаётся незавершённой задачей качества.

GigaAM v2 INT8 остаётся основным и default. Whisper tiny остаётся в APK как экспериментальный альтернативный backend. Веса и точность вычислений не меняются.

Два представления и копирование чистого текста используют текущие строки Room. Физические сегменты не переписываются при объединении для чтения; сохранены ID, временные границы, правки и воспроизведение в диалоге.

При сильном thermal status приложение ждёт до начала следующей тяжёлой операции. Ожидание отменяемо; нативный ASR/diarization уже начавшийся вызов не стал мгновенно прерываемым. Температурные защиты Android/OEM не отключаются.

## Следующая физическая приёмка

На остывшем vivo: установить APK поверх существующего, выбрать GigaAM и «Один говорящий», обработать копию исходного монолога один раз. Сохранить диагностический JSON из приложения и только `ReplikaPerf` Logcat. Отдельно проверить несколько независимых записей с известными участниками, размеченными сменами и словами у проблемных границ. При SEVERE продолжительные сравнения прекратить и дождаться охлаждения.
