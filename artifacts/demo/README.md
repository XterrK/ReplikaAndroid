## Что показывает видео

Все кадры приложения — настоящие записи экрана REPLIKA 1.7 (code 9), снятые на телефоне
vivo V2515 (Android, ARM) через `adb shell screenrecord`. Ускоренные участки помечены в кадре
(«×1,5», «×2», «×6», «×3»).

| Время | Сцена | Что видно |
| --- | --- | --- |
| 0:00 | Вступление | «Встреча закончилась. Стенограмма уже готова. Без интернета.» |
| 0:04 | Титул | иконка и название REPLIKA |
| 0:08 | Запись | касание пузыря → запись; частицы летят от звука, пузырь тянется за касанием (×1,5) |
| 0:18 | Импорт | «Импорт аудио или видео» → выбор файла (×2) → обработка стартует сама: декодирование, диаризация, уточнение говорящих, распознавание GigaAM v3 (×6) |
| 0:28 | Стенограмма | реплики по говорящим и время, плеер, нажатие на реплику, «Аналитика встречи» — доли и время речи каждого (×2) |
| 0:38 | Результаты | на дропе музыки: WER с пунктуацией 23,3% → 13,3% (dev), на Android 17,0% → 9,7%; DER 43% → 18%, верное число говорящих 5/23 → 16/23; RTF 0,35–0,41 на телефоне; до 8 ч при памяти ≤ 0,92 ГБ; язык RU/EN 28/28 |
| 0:50 | Экспорт | «Сохранить JSON для жюри в файл» → системный диалог → «Файл сохранён» + фрагмент JSON (×3) |

Формат JSON в кадре — настоящий экспорт этой записи:
`{"transcript":[{"speaker_id":"speaker_1","start_ms":400,"end_ms":4120,"text":"Да, но это значит больше работы. Надо быть готовыми."}]}`.

## Устройство и ограничения записи

- Обрабатывается тестовая запись стенда (`dev01`, русский, 70 с, 3 говорящих), импортированная
  как `meeting-three-speakers.wav`. 69-секундный файл на телефоне обработан примерно за 30 с,
  включая загрузку моделей; в ролике этот участок ускорен ×6. Скорость на этом же телефоне:
  RTF 0,35–0,41 — см. `artifacts/test-results/step-12-device/README.md`.
- В этой записи автоматическая диаризация нашла 2 говорящих вместо 3 (поэтому в «Аналитике» 51% / 49%).
  Это реальный результат приложения, а не монтаж; автоматическое число говорящих остаётся
  известным ограничением (см. DER выше).
- Частицы на экране записи — от реального звука в микрофон телефона: во время съёмки рядом
  с телефоном проигрывалась та же тестовая встреча через колонки компьютера. Черновик
  записи после съёмки удалён.
- Статус-бар телефона обрезан при монтаже (в нём были личные уведомления); библиотека
  записей в кадр не попадает намеренно — на телефоне есть личные записи владельца.
- Цифры в сцене «Результаты» взяты из `docs/TEST_RESULTS.md` и `docs/STEP_*.md`.

## Как пересобрать ролик

Проект HyperFrames лежит вне репозитория (`C:\R\replika-video`): `build_comp60.py` генерирует
`composition60/`, затем `npx hyperframes@0.9.20 check` и
`npx hyperframes@0.9.20 render --quality delivery`, после чего постер вшивается в кадр 0.
Исходные записи экрана с телефона — `C:\R\demo-footage-phone`. Прежняя 2-минутная версия
(футажи с эмулятора) — `build_comp.py` → `composition/`, `C:\R\demo-footage`.
