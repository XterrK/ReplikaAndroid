## What can be reused

| Operation | Proven behavior | Consequence for this sweep |
| --- | --- | --- |
| Reuse one `OfflineSpeakerDiarization` object | Its constructor creates segmentation, embedding and clustering objects. `set_config` replaces only clustering. | Save model-loading cost across thresholds for the same embedder/settings; process configurations sequentially on that object. |
| Change threshold or `num_clusters` with `set_config` | Only `config.clustering` is copied. Other config fields are ignored. | Recreate the object when changing embedder, threads, provider, shift, min-on or min-off. Explicitly set current min-on **0.2**, not the Python constructor default 0.3. |
| Call `process` again | Segmentation is run again; the multi-window path computes embeddings again before clustering. | This is actual neural inference for every threshold, even with loaded-model reuse. There is no public exact neural-output cache. |
| Read returned results | The result exposes segment counts/sorts; segments expose start/end/speaker/duration/text/confidence. | No segmentation tensor, per-window embeddings or extraction sample-index map is returned. Final turns cannot reconstruct these hidden intermediates. |

These behaviors are explicit in the pinned [public header](https://github.com/k2-fsa/sherpa-onnx/blob/af2d8d81dbfa61c4cea4c568da78f3982edca005/sherpa-onnx/csrc/offline-speaker-diarization.h#L70-L75), [implementation](https://github.com/k2-fsa/sherpa-onnx/blob/af2d8d81dbfa61c4cea4c568da78f3982edca005/sherpa-onnx/csrc/offline-speaker-diarization-pyannote-impl.h#L69-L166) and [result class](https://github.com/k2-fsa/sherpa-onnx/blob/af2d8d81dbfa61c4cea4c568da78f3982edca005/sherpa-onnx/csrc/offline-speaker-diarization-result.h#L21-L76).

The installed Python surface is `process(samples, callback=None)`, `set_config(config)`, `sample_rate`. The binding accepts a copied `std::vector<float>` and does not release the Python GIL around `Process`. Use separate processes for parallel jobs, not a Python thread pool. A maximum of two inference processes is sensible under the current 8 GB/emulator constraint; it is an operational cap, not a measured memory guarantee. [Pinned Python binding](https://github.com/k2-fsa/sherpa-onnx/blob/af2d8d81dbfa61c4cea4c568da78f3982edca005/sherpa-onnx/python/csrc/offline-speaker-diarization.cc#L99-L128).

There is an important short-recording exception: a single segmentation window returns through a special branch before embeddings/clustering. Local model metadata says `window_size=160000` at 16 kHz, so recordings of at most **10 s** take that branch. Their threshold/embedder/fixed-K comparisons do not exercise clustering. In particular, `dev-mono-s` must retain this qualification. The callback's return value is ignored at both invocation sites in this implementation; a nonzero callback return is not a reliable cancellation mechanism despite the Python docstring. An external worker timeout is preferable. [Single-window path](https://github.com/k2-fsa/sherpa-onnx/blob/af2d8d81dbfa61c4cea4c568da78f3982edca005/sherpa-onnx/csrc/offline-speaker-diarization-pyannote-impl.h#L103-L166), [window construction](https://github.com/k2-fsa/sherpa-onnx/blob/af2d8d81dbfa61c4cea4c568da78f3982edca005/sherpa-onnx/csrc/offline-speaker-diarization-pyannote-impl.h#L297-L330), [embedding callback](https://github.com/k2-fsa/sherpa-onnx/blob/af2d8d81dbfa61c4cea4c568da78f3982edca005/sherpa-onnx/csrc/offline-speaker-diarization-pyannote-impl.h#L580-L582).

## Separate public embeddings are available

`SpeakerEmbeddingExtractor.create_stream()`, stream `accept_waveform(16000, samples)` / `input_finished()`, `is_ready(stream)`, and `compute(stream)` expose a real vector. They can support the planned clean-window refiner, but do not expose the private vectors used by `OfflineSpeakerDiarization`. The private extraction path removes overlapping frames and concatenates selected sample runs; a new 1.5 s clean-window extractor is a separate algorithm. [Extractor binding](https://github.com/k2-fsa/sherpa-onnx/blob/af2d8d81dbfa61c4cea4c568da78f3982edca005/sherpa-onnx/python/csrc/speaker-embedding-extractor.cc), [private extraction](https://github.com/k2-fsa/sherpa-onnx/blob/af2d8d81dbfa61c4cea4c568da78f3982edca005/sherpa-onnx/csrc/offline-speaker-diarization-pyannote-impl.h#L505-L575).

Public `FastClustering(config)(features)` accepts a contiguous 2-D Float32 matrix and returns labels. Its cosine-distance complete-linkage implementation normalizes input rows **in place**. Pass a fresh contiguous copy of immutable cached vectors for each experiment; repeated normalization must not mutate the cache. Positive `num_clusters` uses a fixed-K tree cut; otherwise threshold determines the cut. It returns labels, not the hidden diarization reconstruction state. [Python clustering binding](https://github.com/k2-fsa/sherpa-onnx/blob/af2d8d81dbfa61c4cea4c568da78f3982edca005/sherpa-onnx/python/csrc/fast-clustering.cc#L45-L76), [clustering implementation](https://github.com/k2-fsa/sherpa-onnx/blob/af2d8d81dbfa61c4cea4c568da78f3982edca005/sherpa-onnx/csrc/fast-clustering.cc#L23-L84).

An exact internal segmentation/embedding cache would require a separately reviewed native API change or a parity-validated reimplementation of the private pipeline. Neither is justified merely to label a cheap clustering sweep as the current native implementation.

The pinned [CMake dependency](https://github.com/k2-fsa/sherpa-onnx/blob/af2d8d81dbfa61c4cea4c568da78f3982edca005/cmake/hclust-cpp.cmake#L4-L7) is hclust-cpp tag `2026-02-25`, archive SHA256 `8f14e024c709d73afb40ae69cb22de4b73dba67cbce40f2e518813da8139ab56`. Its [cutree_k guard](https://github.com/csukuangfj/hclust-cpp/blob/2026-02-25/fastcluster.cpp#L37-L44) returns **one cluster** when requested K exceeds the number of feature rows. This avoids the suspected negative-index failure but makes fixed K=8 unsuitable as a general overclustering initializer. A low automatic distance threshold is preferable when the internal row count is unknown. Downloaded `fastcluster.cpp` source SHA256: `905d378d59d15bc7989f693ab74d8cf668a7192a5b13e6cd9c1f09f87f892894`; no clustering/model call was made.

Requested K also does not guarantee that K IDs survive into final segments. After clustering, the pipeline's [frame finalization](https://github.com/k2-fsa/sherpa-onnx/blob/af2d8d81dbfa61c4cea4c568da78f3982edca005/sherpa-onnx/csrc/offline-speaker-diarization-pyannote-impl.h#L697-L719) selects per-frame winners, then [segment filtering](https://github.com/k2-fsa/sherpa-onnx/blob/af2d8d81dbfa61c4cea4c568da78f3982edca005/sherpa-onnx/csrc/offline-speaker-diarization-pyannote-impl.h#L779-L790) removes short results. Fewer final speaker IDs alone therefore cannot prove that `set_config` was ignored. A fresh-object control plus recorded actual config/model/turn hashes is needed before attributing a cause.

## Recommended acceptance and provenance

1. First record current embedder/config at automatic threshold **0.50**, then a separate per-case fixed-K diagnostic. Mark fixed-K `oracle_count_used=true`, `research_only=true`, `promotable=false`; never mix its figures into automatic acceptance. Call the diarizer directly even for oracle K=1: production's single-speaker bypass would test a different path. Annotate the <=10 s clustering exception.
2. Then run the dev8 automatic grid with `num_clusters=-1`, integer percentage IDs **30,35,...,95** divided by 100, all other settings fixed. This is 14 thresholds, including the original 0.50. Retain every result, failure and effective Float32 threshold. One object per embedder/process may be reused; every full `process` call remains new diarization inference.
3. Report micro corpus native DER at collar 0 and 250 ms, miss/false-alarm/confusion components, overlap treatment, native count exact rate/MAE, per-case values and replay cpWER. Keep native-turn DER separate from projected-transcript DER. Freeze the selection rule before reading the grid; do not choose only by count error while ignoring activity/identity errors. A reasonable proposal is primary native DER0 improvement with DER250/count/cpWER regressions treated as explicit guards or declared tradeoffs, not hidden averaging.
4. Run clean-window refiner embeddings as their own measured neural stage. Windows must come only from predicted activity/turns, exclude predicted overlap, and preserve the original PCM. Freeze width/hop and all filtering before evaluating tau variants. Cache actual vectors with window sample coordinates and validate finite, nonzero vectors. If the source turns or window selection change, the cache key must change.
5. Replay frozen **D context600** ASR tokens/text/timestamps for C's cpWER/raw-WER diagnostics. Reparse words and assign them to each candidate's new turns; do not reuse D's old speaker labels or speaker warnings. Keep the same per-chunk grouping/punctuation policy and verify the ordered raw token stream is unchanged. This avoids new ASR inference and does not provide reference text/counts to automatic inference.
6. Keep the original holdout and the reserve as separate mandatory regression validations. Both have already been examined during D; neither is a fresh blind C holdout. Their actor montage DER remains an utterance-placement proxy. Do not promote C based solely on oracle-K results or proxy improvements without preserving that scope.

Use stage-specific provenance, for example `diarization.new_model_inference=true`, `asr.new_model_inference=false`, `asr.replay_source=<path+SHA>`. A pure refiner parameter replay from a feature cache has `new_model_inference=false` for that replay, while pointing to the earlier real embedding extraction. A run-level “any neural inference happened” marker may additionally remain true. Cached and fresh results must never share an ambiguous speed claim.

Cache/run fingerprints should include:

- Actual audio SHA, decoded Float32 PCM SHA/sample count/rate and decoder/helper hashes.
- Segmentation and embedder file SHA/size, model metadata and lock/catalog revision; runtime version, full git, ORT version, extension hash, platform/CPU/provider/threads.
- Every effective configuration field, explicit automatic/oracle mode, min-on/off, window shift, clustering threshold/K/confidence flag; candidate code and scorer hashes.
- For clean-window features: source predicted-turn/VAD hashes, window sample coordinates/order, selection code/config, input gain policy, extractor settings, output dtype/shape/vector bytes SHA. Exclude reference text and reference speaker labels from feature-cache identity.
- ASR replay source run/config/diagnostics and token/text/timestamp SHA; separately fingerprint scoring references and selected IDs for scored reports.

Store actual diarization/model-load/refiner/replay/scoring times separately. A saved-ASR sweep is not a measured full pipeline; reconstructing a total from historical stage times is only an explicitly labelled estimate. Two concurrent jobs are quality experiments, not controlled RTF comparisons.

For later independent natural-dialogue validation, the official [VoxConverse repository](https://github.com/joonson/voxconverse) supplies real multispeaker video audio links and RTTM dev/test labels, with corrected annotation version **0.3**. A metadata-frozen subset could test native DER independently of the current actors/montages. It would be cross-domain evidence, not Russian ASR/word-timing acceptance. Pin its annotation commit, license, audio hashes and selection before inference. No corpus files were fetched here.
