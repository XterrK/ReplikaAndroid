# C: Android integration review before host acceptance

Read-only inspection, 2026-11-07. Only this report was added. No Android draft/source, model lock/pack, weights, SDK, build, Git operation or model inference was performed. C host gates are not established; V1.6 remains unchanged. The existing D context600 opt-in is independent of the proposed C integration.

## Exact seam and current implementation

There is no separate `DiarizationEngine` implementation in this tree. [ProcessingWorker](../../../app/src/main/java/ru/replika/ml/ProcessingWorker.kt), lines145–161, owns the current native stage: single-speaker bypass, memory check, original full-recording PCM, `OfflineSpeakerDiarization.process`, Float32 seconds→rounded milliseconds, `Alignment.stable`, and `sd.release()` in `finally`. The optional refiner belongs **after that stable native-turn result and release, before alignment/planning at line162 and word assignment**. Keep raw turns separately; use refined turns only in an explicitly selected accepted C profile. Do not rerun ASR to compare speaker postprocessing.

The existing branches are semantically important: [MlPolicy](../../../app/src/main/java/ru/replika/domain/TranscriptPresentation.kt) maps expected1 to `single`, 2..20 to user-selected `fixed`, and -1 to `automatic`. Preserve single bypass without segmentation/embedding/full-recording allocation. Preserve explicit fixed counts, including >8: a refiner with hard K<=8 must not silently override those user choices. Initial overcluster8 is a **global seed policy for automatic mode**, not a reason to write8 into the recording's requested `expectedSpeakers=-1`.

Recommended control seam: a separate persisted `DiarizationPlan`/WorkData key, with missing historical input resolving to legacy; unknown IDs fail explicitly. Append the selector to enqueue/QA APIs without reinterpreting existing positional ASR arguments. Keep an ordinary-build legacy default and explicit candidate-build/QA opt-in. [AsrPlan](../../../app/src/main/java/ru/replika/domain/AsrPlan.kt) and its seven-field ASR policy stay unchanged: choosing C must not also change VAD/context/punctuation.

## Public embeddings and native availability

It does not honor the selected manifest path or sequential release policy. A worker-local extractor is sufficient; a cross-recording enrollment manager is unnecessary.

## Extraction, cancellation and resources

Keep [ModelManager.gate](../../../app/src/main/java/ru/replika/ml/ModelManager.kt) held through model validation, native diarization, extra extraction, refinement and ASR, as today. It prevents model deletion/replacement or another worker's concurrent ML sessions. Release `sd` before constructing the separate extractor; do not keep two embedding sessions alive for convenience. Release each stream in `finally`, then release the extractor in an outer `finally`, before ASR load. These wrappers require explicit `release`; finalizers are a fallback, not a resource policy.

Plan the exact host windows from **predicted** native turns: same-label interval union; exclude every other/unknown label overlap; 1500ms windows every750ms; an exclusive island of1000..1499ms uses its actual whole span; <1000ms produces missing-centroid evidence. No padding, reference intervals, VAD-generated gold, transcript hints or speaker-count hints. These are predicted-clean windows, not a claim of acoustically perfect single-speaker speech.

Read original cached PCM with [AudioDecoder.read](../../../app/src/main/java/ru/replika/ml/AudioDecoder.kt), lines96–113. Validate millisecond→sample conversion using Long before Int (`ms*16` at16kHz), require bounds within `decoded.samples`, and keep each array <=24000 real samples. Never apply QuietAudioGain to embeddings. The file is internal big-endian Float32; any PCM hash must name its encoding, or use a canonical explicitly defined Float32 byte order on both ports. Do not compare an unlabelled raw-file hash to NumPy native-endian bytes.

Check captured coroutine context before/after each bounded read and each extractor compute; call the existing thermal guard between windows. Native compute is synchronous, so cancellation waits for that call to return. Rethrow `CancellationException`; do not turn cancellation/OOM into a successful fallback. Preserve the existing cancellation/ERROR paths, private incomplete QA evidence, final Room transaction checks and PCM cleanup. Unsupported **algorithm evidence** may retain actual raw turns with explicit support/fallback status; it must not claim successful refinement or publish invented centroids.

Current [PipelineTelemetry](../../../app/src/main/java/ru/replika/ml/PipelineTelemetry.kt) reports stage-boundary PSS, not continuous peak RAM. Add separate window planning/read, extractor load/inference/release and pure-refiner times. Preserve existing native diarization timing meaning and label any combined total explicitly; nested telemetry times cannot simply be summed into whole-pipeline RTF. New extraction incurs real inference cost. Current native RTF problems are not evidence of an available speed budget.

## Pure Kotlin mathematics is still required

Search of production/test Kotlin and dependencies found **no Kotlin eigensolver or SpeakerRefiner**. The `Eigen` occurrence is an ONNX Runtime third-party license, not a callable JVM matrix library. [speaker_refiner.py](../../../tools/eval/speaker_refiner.py) currently uses NumPy `eigvalsh`.

A later pure `domain/SpeakerRefiner.kt` should mirror normalized weighted centroids, strict cosine thresholds, optional complete-link guard, threshold-excess affinity, normalized Laplacian, eigengap tie/flat policies, partial evidence, small/temporal policy, hard cap and smoothing exactly. A deterministic symmetric Double Jacobi eigensolver is feasible without another native/runtime dependency, but requires convergence/residual checks and unsupported handling. K<=8 limits the estimate, **not necessarily matrix dimension**: the host permits up to256 native centroid labels before rejecting. Do not silently inspect only the first8 labels. Ordinary overcluster8 keeps the matrix small.

Before port acceptance, compare pure Kotlin/Python on real saved Float32 embeddings/windows plus controlled zero/nonfinite, near-tau, eigengap ties, all-small, missing220ms, distinct short guest, overlap and forced-cap cases. Float32 input promotion, Double summation/norm, eigenvalue ordering and tolerances can affect discrete merges. A solver failure must retain actual raw turns and an explicit unsupported result.

[prepare_embedded_pack.read_lock](../../../tools/prepare_embedded_pack.py), lines33–49, hardcodes exactly seven entries and only `diar`/`vad` support groups: an eighth file/new group currently fails. [prepare_models.py](../../../tools/prepare_models.py) downloads only lock-pinned files; research [prepare_diar_models.py](../../../tools/eval/prepare_diar_models.py) is not an Android installation path. The selected weights, size/SHA/source/license, source ZIP manifest, bundled verifier and [BundledModelInstaller](../../../app/src/main/java/ru/replika/ml/BundledModelInstaller.kt) must agree. The installer uses manifest-fingerprinted private staging and verifies all entries before publication. Keep legacy validated files and immutable prior APKs; do not bypass its archive/CRC/hash checks or add first-run network dependency to All-in-One.

## Native QA evidence and count semantics

[EvaluationBatchTest](../../../app/src/androidTest/java/ru/replika/EvaluationBatchTest.kt), lines104–159, already takes one global expected-count argument (default-1), stages only id/audio/hash, explicitly passes the ASR plan and checks actual diagnostics. Add a separate explicit global C plan and actual-policy assertion. Never stage per-file manifest expected K or source actors; fixed research runs must remain labelled oracle runs and cannot masquerade as automatic acceptance.

Record the requested count/mode separately from actual initial clustering mode/count. An automatic request remains-1 even if overcluster8 seeds it. `clusterThresholdApplied` is false for an initial fixed8 seed; current `mode==automatic` is insufficient once C is introduced. Preserve requested fixed2..20 and single bypass. Emit raw native count, refined/effective count, missing-centroid labels, unknown count/duration, estimatedK, forced/low-similarity merges, overlap collapses, fallback method, computational support and solver status. Exclude unknown labels from a claimed known-speaker count; do not drop unknown activity from quality diagnostics.

Retain **both raw and refined turns**, with an explicit field saying which turns actually drove ASR word assignment. Coordinate existing `diarizationTurns` semantics with the native collector: silently overwriting the only raw array would invalidate baseline comparisons; retaining only raw while words use refined turns would make word/speaker reconstruction fail. Report raw-native DER, refined-turn DER and transcript projection DER separately. A new canonical C policy should include selected model SHA/settings, seed clustering, shift/min-on/off, window width/hop/minimum, tau, all small/temporal/guard/smoothing/cap fields and algorithm/solver version; compare exact native Float policy values to the host profile.

Full measured window vectors are needed for pure replay/audit, with window/sample bounds, source-turn/PCM/model/config hashes, dtype/dimension and validity. Keep them explicit-QA only. The existing word evidence has a256KiB budget and Room stores one diagnostics string; copying potentially thousands of512-dimensional embeddings into that column risks CursorWindow failures. Prefer a private QA sidecar (streamed, hash+count in bounded Room summary) or another proven bounded export, without a duplicate global array. Collector must validate the complete requested payload, including sidecar SHA/counts, and reject truncated/incomplete/invalid evidence. Summaries alone cannot prove native centroid/eigensolver parity.

Only after host dev/count+DER gates and separate regression validations pass should this port be implemented, compiled and exercised through actual Worker cases. JVM geometry/parity, selected-model extraction on x86_64, exact native policy/evidence reconstruction, manual/single regressions, UI export, All-in-One packaging and explicit ARM/runtime limits remain separate checks. Symbol availability and this design review establish none of those quality/runtime gates.
